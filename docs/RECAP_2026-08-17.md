# Point d'avancement — Exécuteur AllKeyShop — 2026-08-17

Trace écrite du travail de la semaine (10 → 17 août 2026). Rédigé pour la réunion.

## En une phrase

Le pipeline de saisie AllKeyShop lit les offres d'un marchand, les reconnaît, et
**en une seule passe** décide pour chacune : **l'ajouter**, la **ranger dans la
bonne liste**, ou la **skipper** — le tout **sécurisé** (jamais d'action à l'aveugle,
arrêt propre au moindre doute).

## Ce qui a été livré cette semaine

| Sujet | Résultat |
|---|---|
| **Config marchand** | Chaque marchand part de sa propre configuration (règles au même endroit). Migration de Kinguin, Difmark, Instant Gaming, Gamivo, Eneba. |
| **Instant Gaming — région & plateforme** | Correction d'un vrai bug : les offres étaient saisies avec la mauvaise plateforme/région. On lit désormais la vraie info sur la page de l'offre (plus de « GLOBAL » forcé). Durci par 2 audits. |
| **Politique blacklist région** | Global / Europe / US → on rentre ; Latam / Brésil / Asie / Russie → **liste Blacklist** ; le reste → skip. Règle unique, valable pour tous les marchands. |
| **Workflow unifié par page** | Ajout + rangement en listes + skip, en une passe, page par page. |
| **Logiciels** | Les logiciels ayant une page AKS sont saisis avec la bonne édition de licence. |
| **Charte graphique** | Pages d'admin passées à la charte officielle AllKeyShop. |

## Validation en production

Run réel sur **Kinguin** (14 août) : **11 offres ajoutées + 33 offres triées**
automatiquement vers leurs listes, puis **arrêt propre** (fail-closed) sur un aléa
technique passager du feed — aucune action erronée. Le workflow complet est donc
**prouvé en conditions réelles**.

## Qualité & sécurité

- Chaque brique importante est passée en **revue adversariale** (plusieurs
  relecteurs indépendants qui cherchent à casser le code) ; les défauts trouvés ont
  été corrigés. Suite de tests : **> 1 000 tests automatisés, tous verts**.
- **Incident sécurité traité** : un port serveur (interface d'administration) était
  exposé à Internet. Audit complet → **aucune intrusion** (l'accès aux données
  restait protégé par authentification) → port **fermé** et fichiers sensibles
  verrouillés. Documenté séparément.
